# Observing persistence in blockchain systems

**When blockchain resources have no expiry rule, what can we observe?**

The unit of study is a resource under a specific rule. Record the object, the authority or client applying the rule, the relevant observation date or height, what could change the object’s status and who can still access it. A block, a UTXO, a token balance, a contract entry and a network endpoint belong to different parts of the system. The same resource can be examined through several observational perspectives.

## Observations and coverage

| Resource or outcome | Candidate indicator and boundary | Starting evidence |
| --- | --- | --- |
| Growth of ledger history | Sum canonical serialized block bytes over the observed interval, divided by 10⁹ for GB. Report the common start date and coverage. Use a verified baseline to report a total from genesis. Fix which encoding and components are included, such as witness data or receipts. | Daily block count is archived. Coin Metrics documents `BlkSizeByte`. On 23 November 2026, its Community catalog returned no coverage for this metric and a keyless Bitcoin request returned HTTP 403. A controlled Bitcoin node can derive serialized size from canonical blocks returned by [getblock](https://bitcoincore.org/en/doc/30.0.0/rpc/blockchain/getblock/). [Coin Metrics blocks](https://docs.coinmetrics.io/network-data/network-data-overview/network-usage/blocks) |
| Holdings and concentration | Measure supply or balances at a block. Gini requires the underlying positive address balances. A Lorenz curve shows the share of measured value held by the lowest cumulative share of addresses. Report address eligibility, relation to custodians, excluded contracts and denominator. | Issued supply and funded addresses are archived for selected assets. The source exposes labelled exchange custody share for BTC and ETH, which measures the share held at labelled addresses. Keyless requests returned no Community coverage for `SplyAdrTop100`. [Coin Metrics supply](https://docs.coinmetrics.io/network-data/network-data-overview/supply) |
| Dormancy and renewed movement | Share of current UTXO value older than a fixed interval, such as 365 days, divided by all UTXO value in the same snapshot. Separately, sum the value of old outputs spent during each day. An address inactivity measure would instead use an explicitly defined last eligible activity. | Bitcoin’s transaction model gives output creation and spending events. Coin Metrics documents active supply with separate rules for UTXO and account-based assets. The keyless Community catalog returned no coverage for `SplyAct1yr` or `SplyActPct1yr` on 23 November 2026. [Bitcoin transactions](https://developer.bitcoin.org/devguide/transactions.html) · [Coin Metrics active supply](https://docs.coinmetrics.io/network-data/network-data-overview/supply) |
| State retention, renewal and restoration | For a live contract key, remaining TTL is last live ledger minus observed ledger. Measure live entries, archive transitions and restorations individually and document their storage class and protocol version. | Stellar TTL and age since last write are archived for two specific contract-instance keys. TTL snapshots alone do not identify the transitions. [Stellar state archival](https://developers.stellar.org/docs/learn/fundamentals/contract-development/storage/state-archival) |
| Node storage, connectivity and access | Measure disk use by component on a specified node and configuration. Probe the oldest retrievable block, endpoint success rate and latency against fixed requests. Study peer-session duration and off-chain link retrieval success separately. | Observed execution head is archived for supported endpoints. Bitcoin Core exposes a block-and-undo-files disk estimate and pruning fields. IPFS uses reachable providers and retention mechanisms such as pinning for content availability. [Bitcoin Core RPC](https://bitcoincore.org/en/doc/30.0.0/rpc/blockchain/getblockchaininfo/) · [IPFS persistence](https://docs.ipfs.tech/concepts/persistence/) |

For ordered positive address balances $b_i$ and population $n$, one reproducible Gini definition is $G = 2\sum_i i b_i / (n\sum_i b_i) - (n+1)/n$, with ranks starting at one. The population and denominator can change over time even when the formula stays fixed. A defensible measurement must publish the inclusion rules and coverage with each result.

Archive observations can show association. For effects attributable to an expiry or retention policy, a stronger starting point is a matched policy change in one protocol, or a controlled comparison of client configurations with the same chain height, workload and node specification. For example, the Ethereum Foundation documents partial removal of pre-Merge execution history. That provides a retention-policy comparison for disk and historical accessibility, with measurements by specific client and version. It does not establish effects on token holdings. [Ethereum Foundation announcement](https://blog.ethereum.org/2025/07/08/partial-history-exp)

## Interactive design

**Resource and event explorer.** The first interaction is available under Research. Choose a resource and a lifecycle stage. The description changes alongside an available observation or a clearly identified research gap. Shareable URLs retain the chosen resource and stage. The whole study is loaded from the client bundle and only uses the archive when a visitor follows an observation link.

**Time and age controls.** Next, prototype a draggable date cursor and discrete age buttons such as 30, 180 and 365 days. Display the cohort’s value and sample coverage for the same observation date. Annotate threshold crossings separately from actual spends. The age control requires a verified distribution of the unspent set as input.

**Matched comparison.** Show comparable observations on one aligned date axis. For infrastructure, surface client and retention modes before graphing bytes or availability. For holdings, compare Lorenz curves with the corresponding population rules and sample sizes next to the graph. Offer reset, keyboard operation and a table equivalent. Mark all illustrative transitions as documented examples and leave quantitative views empty where measurement inputs are missing.

**Evidence detail.** Keep the object, rule, date or height, formula, source, and interpretation limit adjacent to the observation. A separate rule for a new resource class can extend the same structure to approvals, credentials or referenced content.
